1. DESCRIPCIÓN DEL PROYECTO
────────────────────────────────────────────────────────────────────────────────
App Android para EMT Madrid que convierte la espera activa del bus en espera
pasiva mediante un sistema de notificaciones altamente configurable. El usuario
especifica cuántos minutos de antelación quiere recibir el aviso antes de que
el bus llegue a su parada. Además incluye las funcionalidades estándar de una
app de transporte y un mapa en tiempo real.


────────────────────────────────────────────────────────────────────────────────
2. STACK TECNOLÓGICO
────────────────────────────────────────────────────────────────────────────────
Frontend:       Android Studio (Kotlin/Java)
Backend:        Python (FastAPI — ver código existente en /routers, /services)
Base de datos:  PostgreSQL
API externa:    EMT Madrid API (credenciales ya obtenidas)
Mapas:          Google Maps SDK for Android
                  → Modelo de pago: pay-per-use (sin cuota fija mensual)
                  → Evaluar si Maps SDK básico + quota gratuita cubre el uso

3. ARQUITECTURA — DECISIONES TOMADAS
────────────────────────────────────────────────────────────────────────────────

3.1 NOTIFICACIONES (polling)
  - El polling a la API de EMT lo hace el DISPOSITIVO (cliente Android),
    no el backend. [Decisión: opción B, con apertura a cambiar si es mejor]
  - Mecanismo Android: WorkManager o AlarmManager + Service en background.

3.2 BACKEND
  - El backend actúa como PROXY de la API EMT para proteger la API key
    (no se embebe en el APK).
  [PENDIENTE: confirmar si proxy es requisito o se acepta key en APK
   para simplificar dado el tiempo disponible]
  - Vive en LOCALHOST durante desarrollo y entrega del TFC.

3.3 AUTENTICACIÓN
  - La app NO requiere registro ni login de usuario.
  - Los datos de usuario (favoritos, historial, alertas programadas) se
    almacenan localmente en el dispositivo (Room DB o SharedPreferences).

3.4 MAPAS
  - Muestra AMBAS cosas: posición de paradas + posición del bus en tiempo real.
  - La "flecha de dirección" del bus sigue la línea de ruta predefinida,
    no el GPS real del vehículo (suficiente para dar impresión de movimiento).
  - Actualización periódica de posición del bus en el mapa.


────────────────────────────────────────────────────────────────────────────────
4. FUNCIONALIDADES
────────────────────────────────────────────────────────────────────────────────

4.1 FUNCIONALIDAD CORE — Sistema de notificaciones
  Características:
  - Alertas de un solo disparo (se consume tras notificar).
  - Múltiples alertas activas simultáneamente.
  - Altamente configurable. Modos previstos:
      a) ALERTA SIMPLE: avísame cuando al bus X en parada Y le queden N min.
      b) ALERTA PROGRAMADA POR HORA: cerca de las HH:MM, avísame cuando
         al bus X le queden N min (ej: "a las 17:00, cuando queden 5 min").
      c) ALERTA DE PRÓXIMOS N BUSES: avísame de los 2 próximos buses a
         una parada cuando les queden N min (ej: los 2 siguientes a las 17h).
  - La app puede estar en background/cerrada y debe seguir funcionando.

4.2 FUNCIONALIDADES ESTÁNDAR
  - Buscar parada por nombre o número
  - Ver líneas que pasan por una parada
  - Ver tiempos de llegada en tiempo real
  - Ver el recorrido completo de una línea
  - Paradas favoritas
  - Historial de búsquedas recientes

4.3 MAPA
  - Ver posición de paradas en el mapa
  - Ver posición del bus en movimiento (actualización periódica)
  - Indicador de dirección del bus (simulado según ruta predefinida)
  - Ver tiempo restante hasta parada más cercana al usuario
